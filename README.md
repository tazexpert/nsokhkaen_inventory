# ระบบบริหารจัดการวัสดุและครุภัณฑ์ สำนักงานสถิติจังหวัดขอนแก่น

ระบบเว็บแอปพลิเคชันสำหรับบริหารจัดการวัสดุสิ้นเปลืองและครุภัณฑ์ พร้อมระบบ QR Code สำหรับเบิก/ยืม/คืน

**ไม่ต้องติดตั้งผ่าน Composer** — ไลบรารี PHP ทั้งหมดถูกดาวน์โหลดมาเก็บไว้ในโฟลเดอร์ `libs/` ของโปรเจกต์เรียบร้อยแล้ว เพียง `git pull`, รันไฟล์ SQL และแก้ค่า config ฐานข้อมูลก็ใช้งานได้ทันที

## เทคโนโลยีที่ใช้

- PHP 8+ (PDO)
- MySQL
- Bootstrap 5, jQuery (โหลดจาก CDN)
- `libs/phpqrcode/` — ไลบรารี [PHP QR Code](https://github.com/t0k4rt/phpqrcode) (ไฟล์ PHP ล้วน ไม่มี dependency ภายนอก) สำหรับสร้าง QR Code
- `libs/simplexlsx/` — ไลบรารี [SimpleXLSX](https://github.com/shuchkin/simplexlsx) / [SimpleXLSXGen](https://github.com/shuchkin/simplexlsxgen) (ไฟล์คลาสเดี่ยว ไม่มี dependency ภายนอก) สำหรับอ่าน/เขียนไฟล์ Excel (.xlsx)

> ไลบรารีทั้งสองตัวใช้เฉพาะส่วนขยายมาตรฐานของ PHP (เช่น `gd`, `zip`, `simplexml`) ซึ่งมักเปิดใช้งานอยู่แล้วในโฮสติ้ง PHP ทั่วไป ไม่ต้องรัน `composer install`

## การติดตั้ง

1. `git pull` หรือ clone โปรเจกต์นี้ลงเครื่อง/เซิร์ฟเวอร์ (ไม่ต้องรันคำสั่งติดตั้งไลบรารีใดๆ เพิ่มเติม)

2. สร้างฐานข้อมูลและตารางทั้งหมดโดยรันไฟล์ `database/schema.sql` (มีข้อมูลจำลองรวมอยู่ด้วย):
   ```
   mysql -u root -p < database/schema.sql
   ```
   > ถ้าเคยรัน `schema.sql` เวอร์ชันเก่าไปแล้ว ให้รันไฟล์ migration ที่ยังไม่เคยรันตามลำดับแทนการสร้างใหม่ทั้งหมด:
   > - `database/migrations/001_add_material_unit_cost.sql` (คอลัมน์ต้นทุน/หน่วย)
   > - `database/migrations/002_add_settings_and_storage_locations.sql` (เมนูตั้งค่าระบบ + สถานที่จัดเก็บแบบ dropdown)
   > - `database/migrations/003_add_requisitions.sql` (ระบบใบเบิกวัสดุ)
   > - `database/migrations/004_add_images_and_auto_category.sql` (แนบรูปภาพ + หมวดหมู่วัสดุอัตโนมัติ) ตามด้วย
   >   `php database/migrations/004_backfill_material_categories.php` เพื่อจัดหมวดหมู่วัสดุที่มีอยู่แล้วใหม่ตามตัวอักษรไทยตัวแรกของชื่อ
   > - `database/migrations/005_add_borrowers.sql` (ผู้ยืม/PIN สำหรับยืมครุภัณฑ์ - ตารางแยก `borrowers`) ตามด้วย
   >   `database/migrations/006_merge_borrowers_into_users.sql` (ย้ายข้อมูลจาก `borrowers` มารวมกับตาราง `users` แล้วลบตาราง `borrowers` - ถ้าไม่เคยรัน 005 มาก่อน ก็รัน 006 ไฟล์เดียวได้เลย)

3. แก้ไขค่าการเชื่อมต่อฐานข้อมูลในไฟล์ `config/database.php`:
   ```php
   define('DB_HOST', getenv('DB_HOST') ?: 'localhost');
   define('DB_NAME', getenv('DB_NAME') ?: 'nsokhkaen_inventory');
   define('DB_USER', getenv('DB_USER') ?: 'root');
   define('DB_PASS', getenv('DB_PASS') ?: '');
   ```
   (ถ้าไม่ได้ตั้งค่า environment variable ระบบจะใช้ค่า default ที่เขียนไว้หลัง `?:` — แก้ตรงนั้นตรงๆ ได้เลย)

4. ตั้งค่า `APP_URL`/ชื่อระบบ ให้ตรงกับที่อยู่จริงของเว็บ — ทำได้ 2 วิธี (ดูหัวข้อ "ตั้งค่าเมื่อใช้ XAMPP" ด้านล่าง — **สำคัญมากสำหรับ QR Code**):
   - **วิธีที่แนะนำ**: login เป็น admin แล้วไปที่เมนู **"ตั้งค่าระบบ" → "ค่าพื้นฐานระบบ"** แก้ไขและบันทึกได้ทันทีโดยไม่ต้องแตะโค้ด
   - หรือแก้ค่าเริ่มต้นในไฟล์ `database/schema.sql` (แถว `INSERT INTO settings`) ก่อนรัน หรือแก้ตรงๆ ในตาราง `settings` ผ่าน phpMyAdmin

5. ตั้งค่า document root ของเว็บเซิร์ฟเวอร์ให้ชี้มาที่โฟลเดอร์โปรเจกต์ แล้วเปิด `public/index.php`

6. บัญชีผู้ใช้เริ่มต้น (รหัสผ่าน `password123` ทั้งสองบัญชี):
   - `admin` — สิทธิ์ผู้ดูแลระบบ (จัดการได้ทุกระบบ)
   - `staff1` — สิทธิ์เจ้าหน้าที่ (สแกน เบิก ยืม คืน เท่านั้น)

## ตั้งค่าเมื่อใช้ XAMPP (จำลองเป็นเครื่อง server)

QR Code ที่ระบบสร้างขึ้นจะฝัง**ลิงก์เต็ม**ไปที่หน้า `scan.php` ไว้ในตัวโค้ด (เช่น `http://192.168.1.50/nsokhkaen_inventory/public/scan.php?qr=MAT-QR-0001-abcdef`) เพื่อให้กล้องมือถือทั่วไปเปิดหน้าสแกนได้ทันทีโดยไม่ต้องเปิดแอปอะไรเพิ่ม ดังนั้นค่า `APP_URL` ต้องเป็น **ที่อยู่ที่มือถือเครื่องอื่นเข้าถึงเครื่อง PC ได้จริง** ไม่ใช่ `localhost`

ขั้นตอน:

1. **วางโปรเจกต์ในโฟลเดอร์ `htdocs` ของ XAMPP**
   ```
   C:\xampp\htdocs\nsokhkaen_inventory\
   ```

2. **หา LAN IP ของเครื่อง PC** (เครื่องที่รัน XAMPP) — เปิด Command Prompt แล้วพิมพ์:
   ```
   ipconfig
   ```
   ดูค่าแถว `IPv4 Address` เช่น `192.168.1.50` (ต้องเป็น IP วงเดียวกับมือถือที่จะใช้สแกน คือต่อ WiFi เดียวกัน)

3. **ตั้งค่า APP_URL ให้ตรงกับ IP ที่ได้** (**อย่าใช้ `localhost`** เพราะมือถือเครื่องอื่นจะเข้าไม่ถึง) — login เป็น admin แล้วไปที่เมนู **ตั้งค่าระบบ → ค่าพื้นฐานระบบ** ใส่ค่าเช่น `http://192.168.1.50/nsokhkaen_inventory/` แล้วกดบันทึก ตัวระบบ (เมนู, redirect, QR Code ที่พิมพ์ใหม่) จะใช้ path จากค่านี้โดยอัตโนมัติทันที

4. **เปิดพอร์ตในไฟร์วอลล์ของ Windows** ให้ Apache (พอร์ต 80 หรือพอร์ตที่ XAMPP ตั้งไว้) รับการเชื่อมต่อจากเครื่องอื่นในวง LAN ได้ (Windows Defender Firewall → Allow an app → เลือก Apache HTTP Server หรือเปิดพอร์ต 80 ขาเข้า)

5. **ทดสอบจากมือถือ**: เข้า WiFi วงเดียวกับ PC แล้วเปิดเบราว์เซอร์ไปที่ `http://192.168.1.50/nsokhkaen_inventory/public/index.php` — ถ้าเห็นหน้า login แสดงว่าตั้งค่าถูกต้อง พร้อมพิมพ์สติ๊กเกอร์ QR Code ไปแปะและใช้กล้องมือถือสแกนได้จริง

6. **ถ้าจะใช้งานเฉพาะบนเครื่อง PC เครื่องเดียว** ใช้ `http://localhost/nsokhkaen_inventory/` ได้ตามปกติ ไม่ต้องยุ่งกับไฟร์วอลล์ (หน้าสแกนใช้แอปกล้อง/สแกน QR ของเครื่องเสมอ ไม่มีการเปิดกล้องผ่านเบราว์เซอร์)

> เมื่อสแกน QR Code ที่พิมพ์ออกมาแล้วยังไม่ได้ยืนยันตัวตน ระบบจะพาไปหน้ากรอก **PIN 6 หลัก** ก่อน (ไม่ใช่หน้า login ด้วยชื่อผู้ใช้+รหัสผ่าน) และเมื่อกรอก PIN ถูกต้องจะเด้งกลับไปที่หน้าแสดงรายละเอียด/ฟอร์มเบิก-ยืม-คืนของรายการนั้นให้อัตโนมัติ ดูหัวข้อ "หน้าสแกน QR Code ไม่ต้อง login" ด้านล่าง

## โครงสร้างโปรเจกต์

```
├── api/              # AJAX backend endpoints (materials, assets, scan, report, import)
├── assets/           # CSS / JS ฝั่งหน้าเว็บ
├── config/           # การเชื่อมต่อฐานข้อมูลและค่าตั้งต้นของระบบ
├── database/         # schema.sql (โครงสร้างตาราง + ข้อมูลจำลอง)
├── includes/         # ฟังก์ชันกลาง, การตรวจสอบสิทธิ์, header/footer
├── libs/             # ไลบรารี PHP ที่ดาวน์โหลดมาเก็บไว้ล่วงหน้า (phpqrcode, simplexlsx) - ไม่ต้อง composer install
├── public/           # หน้าเว็บที่เข้าถึงได้โดยตรง (document root)
└── uploads/          # โฟลเดอร์ชั่วคราวสำหรับไฟล์ที่อัปโหลด
```

## สิทธิ์การใช้งาน (Role)

- **Admin**: จัดการวัสดุ/ครุภัณฑ์ (CRUD), นำเข้า Excel (.xlsx), พิมพ์ QR Code, ดูรายงาน, ตั้งค่าระบบ, สแกนเบิก/ยืม/คืน, ดูใบเบิกทั้งหมด
- **Staff**: สแกนเบิก/ยืม/คืนผ่านหน้า "สแกน QR Code" และดู/พิมพ์ใบเบิกย้อนหลังที่เมนู "ใบเบิก" เท่านั้น

## บัญชีของฉัน (ทุก Role) — เปลี่ยนรหัสผ่าน / ตั้ง PIN ด้วยตัวเอง

ทุกคนที่ login เข้าระบบ (ทั้ง admin และ staff) แก้ไขบัญชีของตัวเองได้ที่ไอคอน <i class="bi bi-person-gear"></i> มุมขวาบน (`public/account.php`) โดยไม่ต้องให้ admin เข้าไปแก้ให้:

- **เปลี่ยนรหัสผ่าน**: ต้องกรอกรหัสผ่านปัจจุบันให้ถูกต้องก่อนจึงจะเปลี่ยนเป็นรหัสผ่านใหม่ได้
- **ตั้ง/เปลี่ยน/ลบ PIN**: ตั้ง PIN 6 หลักของตัวเอง (สำหรับ login ผ่านหน้า "สแกน QR Code" โดยไม่ต้องพิมพ์ชื่อผู้ใช้/รหัสผ่าน - ดูหัวข้อ "หน้าสแกน QR Code ไม่ต้อง login" ด้านล่าง) ระบบตรวจสอบ PIN ซ้ำให้อัตโนมัติเช่นเดียวกับตอน admin ตั้งให้จากเมนู "ตั้งค่าระบบ"

**ผู้ใช้งาน role Staff ที่ยังไม่เคยตั้ง PIN**: หลัง login ด้วยชื่อผู้ใช้/รหัสผ่านสำเร็จ ระบบจะตรวจสอบอัตโนมัติว่าตั้ง PIN ไว้หรือยัง ถ้ายังจะพาไปหน้า "บัญชีของฉัน" พร้อมข้อความแจ้งเตือนให้ตั้ง PIN ก่อน (กดลิงก์ "ข้ามไปก่อน" เพื่อข้ามได้หากยังไม่สะดวกตั้งตอนนี้) เมื่อตั้งเสร็จจะพากลับไปหน้าที่ตั้งใจจะเข้าแต่แรกให้อัตโนมัติ (รองรับกรณี login มาจากการสแกน QR Code สติ๊กเกอร์ด้วย)

## เมนู "ตั้งค่าระบบ" (Admin เท่านั้น)

- **ผู้ใช้งาน**: เพิ่ม/แก้ไขผู้ใช้, กำหนดสิทธิ์ admin/staff, เปลี่ยนรหัสผ่าน, ปิด/เปิดการใช้งานบัญชี (ลบไม่ได้ถ้ามีประวัติทำรายการอยู่ — ใช้ปิดการใช้งานแทน) ห้ามปิด/ลบบัญชีตัวเอง
- **สถานที่จัดเก็บ**: จัดการรายชื่อสถานที่จัดเก็บ ใช้เป็น dropdown list ในฟอร์มเพิ่ม/แก้ไขวัสดุและครุภัณฑ์ (แทนการพิมพ์ข้อความอิสระ)
- **ค่าพื้นฐานระบบ**: แก้ไข `APP_NAME` และ `APP_URL` ได้จากหน้าเว็บโดยตรง (`BASE_URL` คำนวณอัตโนมัติจาก `APP_URL` แสดงไว้เพื่ออ้างอิงเท่านั้น แก้แยกไม่ได้) และตั้ง**ชื่อ-ตำแหน่งผู้จ่ายวัสดุ/ผู้อนุมัติ**ที่จะพิมพ์ในใบเบิกวัสดุทุกใบ (ดูหัวข้อ "พิมพ์ใบเบิกวัสดุ" ด้านล่าง)

## ระบบใบเบิกวัสดุ (ใบเบิก)

หน้าสแกน QR Code (`public/scan.php`) เปลี่ยนจากสแกนแล้วบันทึกทันทีทีละรายการ เป็นระบบ **ใบเบิก**
ตามแบบฟอร์มกระดาษของสำนักงาน:

1. ก่อนใช้งานหน้าสแกนครั้งแรกของวัน ระบบจะขอให้กรอก **PIN 6 หลัก** เพื่อยืนยันตัวตนผู้ทำรายการ (ครั้งเดียว ไม่ต้องกรอกซ้ำทุกรายการ - ดูหัวขัด "หน้าสแกน QR Code ไม่ต้อง login" ด้านล่าง) จากนั้นสแกน/ค้นหาแต่ละรายการแล้วกด **"เพิ่มลงใบเบิก"** (วัสดุ: ระบุจำนวนที่จะเบิก, ครุภัณฑ์: ระบบใช้ชื่อผู้ที่ยืนยัน PIN ไว้แล้วเป็นผู้ยืมโดยอัตโนมัติ ไม่ต้องกรอก PIN ซ้ำต่อรายการ) — สแกนได้หลายรายการสะสมไว้ในรายการเดียวกัน
2. กรอก **ใช้งานเพื่อ / ชื่อผู้เบิก / ตำแหน่ง** แล้วกด **"บันทึกใบเบิก"** — ระบบจะตัดสต๊อก/เปลี่ยนสถานะครุภัณฑ์เป็น "ถูกยืมอยู่" ให้ทุกรายการพร้อมกันในทรานแซกชันเดียว (ถ้ารายการใดสต๊อกไม่พอ จะยกเลิกทั้งใบเบิก ไม่มีการตัดสต๊อกบางส่วนค้างไว้) และออกเลขที่ใบเบิกอัตโนมัติตามรูปแบบ **เลขรันนิ่ง/ปี พ.ศ.** เช่น `1/2569`, `2/2569`, ... แล้วเริ่มนับ `1` ใหม่ทุกต้นปี
3. หลังบันทึกเสร็จ กดปุ่ม **"พิมพ์ใบเบิก"** เพื่อเปิดแบบฟอร์มพร้อมพิมพ์ (จัดหน้าให้ตรงกับแบบฟอร์มใบเบิกวัสดุกระดาษของสำนักงาน พร้อมช่องลงชื่อผู้เบิก/ผู้จ่าย/ผู้รับพัสดุ) — รายละเอียดช่องลงชื่อแต่ละช่อง ดูหัวข้อถัดไป

### พิมพ์ใบเบิกวัสดุ - ที่มาของชื่อในช่องลงชื่อแต่ละช่อง

ใบเบิกวัสดุที่พิมพ์ (`requisition_print.php`) มีช่องลงชื่อ 3 ช่อง ซึ่งดึงชื่อ-ตำแหน่งมาจากคนละแหล่งกัน:

- **ผู้เบิก**: ชื่อ-ตำแหน่งของ**บัญชีที่ล็อกอินบันทึกใบเบิกนั้น** (ดึงจากตาราง `users` อัตโนมัติ) ไม่ใช่ช่อง "ชื่อผู้เบิก/ตำแหน่ง" ที่พิมพ์ในฟอร์ม เพราะช่องนั้นอาจพิมพ์แทนคนอื่นก็ได้
- **ผู้จ่าย**: ชื่อ-ตำแหน่งที่ตั้งไว้ล่วงหน้าที่เมนู **"ตั้งค่าระบบ" → "ค่าพื้นฐานระบบ" → "ผู้ลงนามในใบเบิกวัสดุ"** (เพราะปกติเป็นเจ้าหน้าที่พัสดุคนเดิมทุกใบ ไม่ต้องพิมพ์เองทุกครั้ง)
- **ผู้รับพัสดุ** (ใต้หัวข้อ "อนุญาติให้เบิกได้"): ชื่อ-ตำแหน่งผู้อนุมัติ ตั้งไว้ที่เมนูเดียวกัน

ถ้ายังไม่ได้ตั้งค่าผู้จ่าย/ผู้อนุมัติ หรือบัญชีผู้เบิกยังไม่ได้กรอกตำแหน่งไว้ ช่องนั้นจะพิมพ์เป็นเส้นประว่างให้เซ็นด้วยมือแทน
4. การ "คืน" ครุภัณฑ์ยังคงเป็นการสแกนแล้วบันทึกทันทีแบบเดิม (ไม่ต้องผ่านใบเบิก)

**เมนู "ใบเบิก"** (มองเห็นได้ทั้ง admin และ staff) แสดงรายการใบเบิกทั้งหมด ค้นหาด้วยเลขที่/ชื่อผู้เบิก/งานที่ใช้ และ**เลือกช่วงวันที่เรียกดูได้** — **คลิกที่เลขที่ใบเบิก**เพื่อดูรายละเอียดเต็ม (`requisition_view.php`) ภายใต้ header/theme เดียวกับหน้าอื่นๆ ของระบบ ส่วนปุ่ม **"พิมพ์"** เปิดแบบฟอร์มพิมพ์ (`requisition_print.php`, ไม่มี header/theme เพราะจัดหน้าให้ตรงกับแบบฟอร์มกระดาษ) ไว้สำหรับพิมพ์โดยเฉพาะ

## หน้าสแกน QR Code ไม่ต้อง login — ยืนยันตัวตนด้วย PIN ครั้งเดียวต่อรอบการใช้งาน

หน้า "สแกน QR Code" (`public/scan.php`) **ไม่ต้อง login ด้วยชื่อผู้ใช้+รหัสผ่าน** เหมือนหน้าอื่นๆ ของระบบ
เพื่อไม่ให้ยุ่งยากสำหรับคนที่แค่มาเบิก/ยืมของเป็นครั้งคราว:

- เปิดหน้าสแกนครั้งแรก (หรือสแกนสติ๊กเกอร์ QR Code จากแอปกล้องของเครื่อง) ระบบจะพาไปหน้า **กรอก PIN 6 หลัก** (`public/scan_login.php`) ก่อนเสมอ
- กรอก PIN ถูกต้อง **ระบบจะล็อกอินให้ทันที** (เหมือนล็อกอินด้วยชื่อผู้ใช้+รหัสผ่านทุกประการ ใช้ session เดียวกัน) **ไม่ต้องกรอก PIN ซ้ำอีก**ตลอดรอบการใช้งานนั้น ไม่ว่าจะสแกนเพิ่มรายการ บันทึกใบเบิก หรือคลิกไปเมนูอื่นอย่าง "แดชบอร์ด"/"ใบเบิก" ก็เข้าได้เลยโดยไม่ถูกพาไปหน้า login ด้วยชื่อผู้ใช้+รหัสผ่านอีก แม้จะปิดแอปกล้องแล้วสแกนสติ๊กเกอร์ใหม่ (ซึ่งเปิดหน้าเว็บใหม่ทุกครั้ง) ก็ยังจำตัวตนเดิมได้ตราบใดที่ session ยังไม่หมดอายุ/ไม่ได้กด "เปลี่ยนผู้ใช้"
- คนที่ระบุตัวตนด้วย PIN จะกลายเป็น **"ผู้ยืม"** ของครุภัณฑ์ทุกชิ้นที่เพิ่มลงใบเบิกในรอบนั้นโดยอัตโนมัติ (ไม่ต้องกรอก PIN แยกต่อรายการอีกแล้ว) และเป็นผู้บันทึกรายการเบิกวัสดุ/คืนครุภัณฑ์ด้วย
- กดปุ่ม **"เปลี่ยนผู้ใช้"** ที่มุมขวาบนของหน้าสแกน เพื่อออกจากระบบตัวตนปัจจุบันแล้วกรอก PIN ใหม่ (เช่น เปลี่ยนมือให้อีกคนมาสแกนต่อ)
- สิทธิ์การใช้งานหลัง login ด้วย PIN ยังคงเป็นไปตาม role ของบัญชีนั้นตามปกติ (ปกติจะเป็น staff) เมนูที่สงวนไว้สำหรับ admin เท่านั้น (จัดการวัสดุ/ครุภัณฑ์, รายงาน, ตั้งค่าระบบ) ยังคงเข้าไม่ได้เว้นแต่บัญชีนั้นมี role เป็น admin
- เจ้าหน้าที่ (staff/admin) ที่ login ด้วยชื่อผู้ใช้+รหัสผ่านตามปกติก็ใช้หน้าสแกนได้โดยไม่ต้องกรอก PIN เช่นกัน (ถือว่ายืนยันตัวตนแล้วจากการ login)

ผู้ยืม/ผู้ที่กรอก PIN กับผู้ใช้งานระบบ**ใช้ตาราง `users` เดียวกัน** ไม่ได้แยกเป็นตารางต่างหาก โดยแต่ละคนในตารางนี้จะมี:

- **ชื่อผู้ใช้ + รหัสผ่าน** (สำหรับ login เข้าระบบทุกเมนู) เท่านั้น, หรือ
- **PIN 6 หลัก** (สำหรับเข้าหน้าสแกนโดยไม่ต้อง login) เท่านั้น, หรือ
- **ทั้งสองอย่าง** พร้อมกันก็ได้

รายละเอียดเพิ่มเติม:

- จัดการผู้ใช้งานทั้งหมด (ตั้ง/แก้ไข/ลบ username+password และ/หรือ PIN) ได้ที่เมนู **"ตั้งค่าระบบ" → "ผู้ใช้งาน"** (admin เท่านั้น) — PIN แต่ละคน**ต้องไม่ซ้ำกัน** ระบบตรวจสอบให้อัตโนมัติตอนตั้ง/แก้ไข PIN
- PIN ถูก**เก็บแบบ hash ในฐานข้อมูล** (`password_hash()`) เหมือนรหัสผ่านผู้ใช้งานระบบ ไม่สามารถกู้คืนดูค่าดิบได้ ลืม PIN ต้องตั้งใหม่ (หรือกดลบ PIN เดิมได้จากหน้าแก้ไขผู้ใช้งาน)
- การดู/พิมพ์ใบเบิกย้อนหลังที่เมนู "ใบเบิก" เข้าได้ตามปกติหลัง login ด้วย PIN เช่นกัน เพราะ PIN ถือเป็นการ login แบบเต็มรูปแบบเหมือนชื่อผู้ใช้+รหัสผ่าน ไม่ใช่สิทธิ์แบบจำกัดอีกต่อไป

### สแกนด้วยแอปกล้องของเครื่อง

หน้าสแกน QR Code **ไม่มีปุ่มเปิดกล้องผ่านเบราว์เซอร์** (ตัดออกเพราะระบบติดตั้งใช้งานผ่าน LAN ภายในหน่วยงานด้วย `http://` ธรรมดา ซึ่งเบราว์เซอร์มือถือหลายตัว โดยเฉพาะ Safari บน iOS และ Chrome บน Android จะบล็อกการขอใช้กล้องถ้าไม่ได้เปิดผ่าน HTTPS) ให้**ใช้แอปกล้อง/สแกน QR ของเครื่องแทนเสมอ** เพราะ QR Code ทุกใบที่พิมพ์ฝังลิงก์ `scan.php?qr=...` ไว้อยู่แล้ว สแกนด้วยกล้องปกติของมือถือก็เปิดหน้าเว็บมาเพิ่มรายการให้อัตโนมัติ หรือจะพิมพ์/วางรหัส QR ลงช่อง "กรอกรหัส QR ด้วยตนเอง" ในหน้าเว็บโดยตรงก็ได้เช่นกัน

รายการที่ "เพิ่มลงใบเบิก" แล้ว **จะถูกเก็บไว้ในเซสชันฝั่งเซิร์ฟเวอร์** (ไม่ใช่แค่ตัวแปรในหน้าเว็บ) ดังนั้นสแกนสติ๊กเกอร์ใบที่ 2, 3, ... ด้วยแอปกล้องของเครื่อง แม้แต่ละครั้งจะเปิดหน้า `scan.php?qr=...` เป็นหน้าใหม่ทุกครั้งก็ตาม รายการที่เพิ่มไว้ก่อนหน้าจะยังอยู่ครบ (ตราบใดที่ยัง login ค้างอยู่ในเบราว์เซอร์เดียวกัน) กดปุ่ม "ล้างรายการทั้งหมด" ที่หัวการ์ดใบเบิกเพื่อเริ่มใบใหม่ได้ตลอดเวลา

## แดชบอร์ด

กล่องสรุปทั้ง 4 กล่อง (รายการวัสดุ, วัสดุใกล้หมดสต๊อก, รายการครุภัณฑ์, ครุภัณฑ์ที่ถูกยืมอยู่) คลิกได้ (สำหรับ admin) เพื่อไปหน้ารายละเอียดพร้อมตัวกรองที่ตรงกับกล่องนั้นทันที เช่น กล่อง "วัสดุใกล้หมดสต๊อก" จะพาไปหน้าวัสดุพร้อมติ๊กช่อง "แสดงเฉพาะวัสดุใกล้หมดสต๊อก" ให้อัตโนมัติ

ตารางด้านล่างแดชบอร์ดมี 2 ส่วน:
- **ใบเบิกล่าสุด** — แสดงใบเบิก 5 ใบล่าสุด (แทนรายการเบิกวัสดุทีละชิ้นแบบเดิม) คลิกเลขที่ใบเบิกเพื่อดูรายละเอียด พร้อมปุ่ม "พิมพ์" และลิงก์ "ดูทั้งหมด" ไปหน้าเมนู "ใบเบิก"
- **การคืนครุภัณฑ์ล่าสุด** — เฉพาะรายการคืนครุภัณฑ์ (การยืมดูได้จากตารางใบเบิกด้านซ้ายแทน เพราะการยืมทุกครั้งต้องผ่านใบเบิกอยู่แล้ว)

## หมวดหมู่วัสดุ และรหัสวัสดุ (ยึดตามรหัสหมวดวัสดุของสำนักงาน)

ในฟอร์มเพิ่ม/แก้ไขวัสดุ ช่อง **"รหัสหมวดวัสดุ"** (category_code เช่น `14111500`) เป็นช่องบังคับกรอก (มี autocomplete จากรหัสที่เคยใช้ไปแล้ว) และเป็นตัวกำหนดทั้งหมวดหมู่และรหัสวัสดุของรายการนั้น:

- **หมวดหมู่** ของวัสดุคือรหัสหมวดวัสดุนี้เอง (ไม่ใช้ตัวอักษรไทยอัตโนมัติแบบเดิมอีกต่อไป) — พิมพ์รหัสที่มีอยู่แล้วหรือพิมพ์รหัสใหม่ก็ได้ ถ้ารหัสนั้นยังไม่เคยมีมาก่อน ระบบจะสร้างหมวดหมู่ให้อัตโนมัติ
- **รหัสวัสดุ** (`material_code`) สร้างจาก **รหัสหมวดวัสดุ + ลำดับที่ในหมวด 2 หลัก** ต่อกันตรงๆ ไม่มีเครื่องหมายคั่น เช่นรหัสหมวด `14111500` รายการแรกในหมวดนี้จะได้รหัส `1411150001`, รายการถัดไปในหมวดเดียวกัน `1411150002` ฯลฯ (เรียงตามหมวดวัสดุ ไม่ใช่เรียงรวมทุกหมวดแบบ `MAT-0001` เดิม)
- การนำเข้าไฟล์ Excel แบบ **"รายงานวัสดุคงเหลือ"** (ดูหัวข้อถัดไป) มีคอลัมน์รหัสหมวดวัสดุอยู่แล้ว จึงกำหนดหมวดหมู่/รหัสวัสดุแบบนี้ให้อัตโนมัติทันทีที่นำเข้า
- รายการที่**ไม่มี**รหัสหมวดวัสดุ (เช่นรายการเก่าที่เพิ่มไว้ก่อนเปลี่ยนมาใช้ระบบนี้ หรือนำเข้าจากไฟล์แบบ "รายละเอียดพัสดุ" ที่ไม่มีคอลัมน์รหัสหมวดวัสดุ) จะไม่มีหมวดหมู่ (แสดง "-") และใช้รหัสวัสดุแบบเดิม `MAT-0001`, `MAT-0002`, ... ไปก่อน

ครุภัณฑ์ยังคงเลือกหมวดหมู่จาก dropdown เองตามปกติ ไม่ได้รับผลกระทบ

## พิมพ์แคตตาล็อกวัสดุ/ครุภัณฑ์

ปุ่ม **"พิมพ์แคตตาล็อก"** ในหน้าวัสดุและครุภัณฑ์ (ข้างปุ่มพิมพ์ QR Code เดิม) เปิดหน้าสรุปรายการทั้งหมด **เรียงกลุ่มตามหมวดหมู่** (หมวดหมู่วัสดุคือรหัสหมวดวัสดุ, หมวดหมู่ครุภัณฑ์คือที่เลือกไว้เอง) แต่ละรายการแสดง:

- รูปภาพที่แนบไว้ (ถ้ามี ถ้าไม่มีแสดงกรอบ "ไม่มีรูป")
- QR Code สำหรับสแกนเบิก/ยืมได้ทันทีจากหน้าแคตตาล็อกเลย (ลิงก์เดียวกับ QR ที่พิมพ์แปะของจริง)
- รหัส, ชื่อ, ราคา/คงเหลือ (วัสดุ) หรือ ยี่ห้อรุ่น/สถานะ (ครุภัณฑ์), สถานที่จัดเก็บ

เหมาะสำหรับพิมพ์เก็บเป็นเล่ม/ติดบอร์ดอ้างอิงว่ามีพัสดุอะไรอยู่หมวดไหนบ้าง

## แนบรูปภาพวัสดุ/ครุภัณฑ์

ฟอร์มเพิ่ม/แก้ไขวัสดุและครุภัณฑ์มีช่องแนบรูปภาพ (JPG, PNG, WEBP, GIF ขนาดไม่เกิน 5MB) ไฟล์จะถูกเก็บไว้ในโฟลเดอร์ `uploads/materials/` และ `uploads/assets/` ตามรหัสของแต่ละรายการ (เช่น `uploads/materials/MAT-0001.jpg`) อัปโหลดรูปใหม่ทับรูปเดิมได้เลย ลบรายการแล้วไฟล์รูปจะถูกลบตามไปด้วย รูปจะแสดงเป็นรูปย่อในตารางรายการ และแสดงเต็มในหน้าสแกน QR Code เพื่อช่วยให้เจ้าหน้าที่ยืนยันได้ว่าสแกนถูกรายการ

## ไฟล์ CSS/JS ไม่อัปเดตหลัง git pull (เบราว์เซอร์ใช้ไฟล์เก่าที่แคชไว้)

ไฟล์ `assets/css/style.css` และ `assets/js/*.js` ทุกไฟล์แนบเลขเวอร์ชันท้าย URL ให้อัตโนมัติ (เช่น `materials.js?v=1234567890`) โดยอิงจากเวลาที่ไฟล์ถูกแก้ไขล่าสุดบนเซิร์ฟเวอร์ ทำให้เบราว์เซอร์ดึงไฟล์ใหม่ทันทีหลัง `git pull` โดยไม่ต้องล้างแคชเอง ถ้ายังเจอพฤติกรรมเก่าอยู่ (เช่น กดบันทึกแล้วบอกสำเร็จแต่ค่าที่แก้ไม่ติด) ให้ลอง hard refresh เบราว์เซอร์สักครั้ง (Ctrl+Shift+R หรือ Cmd+Shift+R)

## หมายเหตุการนำเข้าไฟล์ Excel

รองรับเฉพาะไฟล์ `.xlsx` (Excel 2007 ขึ้นไป) เท่านั้น หากมีไฟล์ `.xls` หรือ `.csv` เก่า ให้เปิดด้วย Excel/LibreOffice แล้ว "Save As" เป็น `.xlsx` ก่อนนำเข้า

กดปุ่ม "ดาวน์โหลดแบบฟอร์มเปล่า (Excel)" ในหน้านำเข้าวัสดุ/ครุภัณฑ์เพื่อดาวน์โหลดไฟล์ที่มีหัวคอลัมน์และแถวตัวอย่างพร้อมกรอกได้ทันที

**การนำเข้าวัสดุ (materials.php) รองรับไฟล์ 3 รูปแบบ ตรวจจับอัตโนมัติไม่ต้องเลือกเอง:**

1. แบบฟอร์มของระบบเอง (header แถวเดียว, คอลัมน์ `name, category_code, unit, unit_cost, stock_qty, min_stock, storage_location, note`) — มีคอลัมน์ `category_code` ให้ระบุรหัสหมวดวัสดุ ถ้าเว้นว่างรายการนั้นจะไม่มีหมวดหมู่และใช้รหัสวัสดุแบบเดิม `MAT-0001`
2. แบบฟอร์ม **"รายละเอียดพัสดุ"** ที่สำนักงานใช้สืบราคาอยู่แล้ว (คอลัมน์ ลำดับที่ / รายละเอียดของพัสดุ / จำนวนหน่วย / ราคาที่ได้มาจากการสืบราคา(หน่วยละ) / จำนวน(หน่วย) / จำนวนเงิน) — อัปโหลดไฟล์เดิมที่มีอยู่แล้วได้เลยโดยไม่ต้องปรับคอลัมน์ใดๆ ระบบจะอ่าน**ชื่อพัสดุ**จากคอลัมน์ B, **ราคาต่อหน่วย**จากคอลัมน์ D และ**จำนวนที่จัดซื้อ**จากคอลัมน์ E มาเป็นสต๊อกเริ่มต้น (แถวที่ไม่มีเลขลำดับ เช่น แถวสรุปยอดรวม จะถูกข้ามอัตโนมัติ) หน่วยนับจะตั้งเป็น "ชิ้น" ให้ก่อน แก้ไขเพิ่มเติมได้ภายหลังจากหน้าแก้ไขวัสดุ — แบบฟอร์มนี้ไม่มีคอลัมน์รหัสหมวดวัสดุ จึงไม่มีหมวดหมู่และใช้รหัสวัสดุแบบเดิม `MAT-0001`
3. แบบฟอร์ม **"รายงานวัสดุคงเหลือ"** ของสำนักงาน (คอลัมน์ ลำดับที่ / รหัสหมวดวัสดุ / รายการ / หน่วยนับ / ยอดตามบัญชี) — ตรวจจับจากหัวคอลัมน์ "รหัสหมวดวัสดุ" ที่เป็นเอกลักษณ์ของแบบฟอร์มนี้ ระบบใช้**ยอดตามบัญชี**เป็นจำนวนคงเหลือเริ่มต้น (`stock_qty`) และใช้**รหัสหมวดวัสดุ** (`category_code`) ในไฟล์กำหนดทั้งหมวดหมู่และรหัสวัสดุ (`material_code` = รหัสหมวดวัสดุ + ลำดับ 2 หลักในหมวด) ให้อัตโนมัติ ถ้าไฟล์มีหลายชีตแยกตามรหัสหมวดวัสดุ ให้รวมทุกชีตเป็นชีตเดียวก่อนนำเข้า (ระบบอ่านเฉพาะชีตแรกของไฟล์)
